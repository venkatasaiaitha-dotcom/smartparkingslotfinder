WTMP COURSE EVALUATION Evaluation Date: 16-11-2026

Project #27: Smart Parking Slot Finder

Problem Statement: Drivers waste excessive time and fuel searching for available parking spaces in congested commercial and urban hubs. This system provides a map-based booking and real-time availability tracking solution to eliminate parking hunting and optimize facility capacity.

Key Evaluation Viva Questions & Model Answers

Q1: How is JWT authentication and password security implemented?

Answer: When a user registers, their raw password is run through bcryptjs.genSalt(10) and hashed via a Mongoose pre-save hook. When logging in, bcryptjs.compare() verifies the credential. Upon match, a JSON Web Token signed with a private secret (jwt.sign({ id })) is issued and stored in localStorage. For all protected endpoints, the token is passed in the Authorization: Bearer <token> header and decoded in the authMiddleware.

Q2: How does the system handle real-time slot state transitions?

Answer: Each parking slot maintains a status enum (available, reserved, occupied, maintenance). When a driver submits a booking (POST /api/bookings), the slot status transitions to reserved. Upon gate check-in (PUT /api/bookings/:id/status), it becomes occupied. When the driver checks out or cancels (DELETE /api/bookings/:id), the slot is automatically released back to available.

Q3: How are the Maps API coordinates rendered?

Answer: We use Leaflet.js connected with OpenStreetMap tile servers. Each parking facility document in MongoDB stores precise geographic coordinates ({ lat, lng }). The frontend renders dynamic divIcons colored according to real-time capacity (green if available > 4, yellow if <= 4, red if full), with interactive popups allowing one-click navigation to the slot booking grid.
